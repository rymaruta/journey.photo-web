# ホームの日本地図: 当たり判定の固定ベクトル（iOS でも同じ数字で試験できる）

2026-11-09・仕様の正本は「日本地図の県の選び方」v4（デザイナーの提案書）。実装は `lib/utils/japanMapHit.ts`、
表は `docs/home-map-hit-vectors.json`（`lib/utils/__tests__/japanMapHit.test.ts` が実装と一致を毎回確かめる）。

## 判定の決め

| 項目 | 値 |
|---|---|
| 形の中 | **必ずその県**（離島も同じ県・偶奇則）。距離 0 |
| 形の外 | 輪郭（辺）までの最短距離が **16px 以内**でいちばん近い県。距離は（単位の距離 × 画面の px/単位） |
| 全国の画面 | **地方**で判定。地方の距離 ＝ その地方の県のうち最も近い県までの距離。北海道・沖縄は県そのものが 1 つの面（沖縄は枠 `OKINAWA_FRAME` ぜんたい・枠までの距離） |
| 拡大した地方 | その地方の県だけ。16px 以内に地方内の県が無く、地方の外の県の形の中なら `switch`（離すと地方ごと切り替えて県を選ぶ） |
| 粘り | いま触れている県（`prev`）を優先。新しい候補が形の中（距離 0）なら粘らない。`prev` が 16px 以内で、新しい候補との差が **6px 以内**なら `prev` のまま。6px を超えて近い別の県があれば切り替え |
| 離したとき | 画面に見えていた県・地方を選ぶ（離した位置で再計算しない） |
| 地方の分け | 九州・沖縄を「九州（7県）」と「沖縄（独立した面）」に分ける。9 地方: 北海道・東北・関東・中部・近畿・中国・四国・九州・沖縄 |

座標は地図の viewBox の単位（幅 360・高さ 461.8）。画面の px/単位 `s` は、基準の地図幅 358px（390px 画面の左右 16px 余白）を、
いまの viewBox の幅で割ったもの（全国 0.9944・関東 約 6）。地方の viewBox は `lib/utils/japanMapView.ts`（箱の外に 3 単位・地図と同じ縦横比・地方の箱を中央へ）。

## 表の読み方（`docs/home-map-hit-vectors.json`）

各行: `id`・`stage`（`全国` か地方名）・`s`・`x`・`y`・`prev`（触れていたもの・`null` 可）・`expect`。
`expect` は `pref:<slug>`・`region:<地方>`・`switch:<slug>`・`null`（どこにも当たらない）。

- 中心の点（46県 × 地方の画面と全国）・端の頂点から海の側へ 0 / 8 / 15.5 / 16.5 / 30px（15.5 は当たり・16.5 は当たらない）
- 沖縄の枠の右から 0 / 15.5 / 16.5px・離島・海・地方ごと切り替え・粘り

iOS（Swift）では、県の形を折れ線にして同じ計算（点と線分の最短距離・光線法の内外）を移し、`expect` の文字列に変換して比べる。
`CGPath` には距離の関数が無いので自前になる。形の元データは `lib/data/prefectureShapes.ts`（EPS 0.1 の間引き・生成物）。

## 作り直し

形のデータ・判定を変えたら:

```
UPDATE_HIT_VECTORS=1 npx vitest run lib/utils/__tests__/japanMapHit.test.ts
```

表を作り直したら iOS 側へも渡す（変わった行が、判定の変化の全部）。
