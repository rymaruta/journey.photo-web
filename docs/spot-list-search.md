# 撮影スポット一覧の検索窓：検索の規則（Web・iOS 共通の正本）

2026-11-09 owner「撮影スポットを探す一覧に検索窓がほしい」（Web と iOS の両方・見た目と検索の規則をそろえる）。
**正本は この文書と `lib/utils/spotListSearch.ts`**（先頭のコメントに同じ規則）。食い違ったら**この規則に iOS を合わせる**。
試験は `lib/utils/__tests__/spotListSearch.test.ts`（下の表の入力→期待を値で固定している）。

## 検索の対象

- 画面: Web は `/spots`（`app/components/SpotListSearch.tsx`）。iOS は撮影スポットを探す一覧の最上部
- データ: 公開しているスポットの名前だけの索引（`/app/data/spot-search.json`・母集合 `visibleSpots`）。
  1行 = スポット名 `n`・英語名 `e`・読み `r`・別名 `a`・地域 `g`（日本は「県 市」・海外は「国 市」を**空白でつないだ字**）・綴り `s`
- 新しい API・費用は足さない。語が入ったときに1回だけ取る

## 規則（正本）

1. **折りたたみ**（入力と各欄の両方へ同じ変換）: NFKC → 小文字 → カタカナをひらがなへ（U+30A1〜30F6・ヽヾ。長音「ー」は残す）
   → **空白・中黒（・）・読点（、，,）・括弧（()（）「」『』）・ピリオド（. 。）を落とす**。濁点・長音・「ヶ／ケ／が」は寄せない
2. **語**: 入力を空白（全角含む）・読点で分け、各語を折りたたむ。空は捨てる。**最大 6 語**（超えた分は無視）。全部の語が当たる行だけ（AND）。
   **先に、語を空白なしでつなげた1語として名前の欄に当てる**（当たればその順位で確定）。外れたときだけ語ごと
3. **名前の欄**（スポット名・英語名・読み・別名）: 完全一致 0・前方一致 1・部分一致 2
4. **地域の欄**（順位 3）。**字の部分一致にしない**:
   - 欄は 国（日本以外）・県・市区町村・「県＋市」「国＋市」をつないだ字、を**別々に**持つ（`g` は折りたたむ**前に**空白で割る）
   - 語が欄で**始まる**、または語が欄の中に**名前として**入っている（`nameIn`）なら当たり
   - 名前として入っている = 前が端・行政区分の字（都道府県市区町村郡）・「州」「地方」で、後ろが端・行政区分の字・「州」「地方」
     （語自身が行政区分の字で終わるときは後ろは問わない）。これで「東京都」の中の「京都」は外れ、「京都府」の「京都」・「足柄下郡箱根町」の「箱根」は当たり
5. **県の読み・英語名**: 語が県の**読み（ひらがな）の前方**（**2 文字以上**）、または**英語名の前方**（**3 文字以上**）なら、
   その県の名前を地域の欄に当てる（「やまがた」「yamagata」「とう」→ 東京都）。
   英語を 3 文字以上にした理由: 「to」で Tokyo・Tottori・Toyama・Tochigi・Tokushima の 5 県が一度に出て、打ちかけで結果が散らかるため
6. **並び**: 行の順位 = 語ごとに当てたときは各語の順位のうち**最も弱い（大きい）もの**。順位の小さい順、同順位は索引の順。語が無いときは並べ替えない
7. **県の一覧への近道**: 県・「海外」の名前・英語名・綴り・読みに全部の語が当たるものを、県の札で出す（最大 8）。
   名前は 前方一致 または 名前として入っている（部分一致にしない）。英語名・綴り・読みは前方一致（英語 3 文字以上・読み 2 文字以上。英語は完全一致なら何字でも）

## 入力・表示

- 打つたびに絞る。**変換中（IME の確定前）は絞らず、確定したら絞る**。Enter はキーボードを閉じるだけ
  - Web: `compositionend` が来ない環境の保険として、入力イベントの `isComposing` を優先し、入力欄を離れたら字に追いつく
- 空・空白だけは「検索なし」（ふだんの一覧）
- 結果: 「公開中の撮影スポットのうち N件が当たりました。」を先頭に、既存の一覧の行（丸い印・名前・地域・›）。最初 30 件・「さらに表示」で 30 件ずつ。
  「さらに表示」を押したら、新しく出た最初の行にフォーカスを移す
- 0件: 「「…」の撮影スポットは見つかりません。」と県の一覧への導線。県の一覧は残す
- 検索窓: 高さ 44・クリア 44・読み上げの名前「撮影スポットを検索」・プレースホルダー「スポット名・県・エリア」
- 件数の読み上げ欄（`role="status"`）は**常に描き、中身だけ入れ替える**
- Web の URL は `?q=` に残す（履歴は積まない・戻ると復元）。**復元中（索引の取得中）は静的な一覧を隠したまま**にして、届いて0件・失敗のときだけ戻す（画面が跳ねない）

## 計測（Web・GA4）

`spots_search`（`search_term_length`・`result_count`）。打ち終えて約 1.5 秒・2 文字以上・同じ語は続けて数えない。
**検索語は送らない**。**復元された `?q=` では送らない（人が打ったときだけ）**。iOS の計測は別。

県名の折りたたみを毎行・毎キーでやっていたのを、県の折りたたみ済みの値をモジュールで1回だけ持ち、語ごとに1回だけ県名の一覧を作る形にした。

## 別札として残すこと（今は変えない）

- Web の「さがす」・地図の検索（`searchSpotRows`・`normalizeSpotName`）は、ひらがな・カタカナを同じに見ない。
  iOS の地図の検索（`MapSearch.fold`）は同じに見る。**この一覧の規則とは別の食い違い**。
  `normalizeSpotName` にかなの折りたたみを足すと `spotAutoLink` のテストが 15 件落ちるので、そろえるなら呼び元ごと見直す
