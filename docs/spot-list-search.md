# 撮影スポット一覧の検索窓：検索の規則（Web・iOS 共通）

2026-11-09 owner「撮影スポットを探す一覧に検索窓がほしい」（Web と iOS の両方・見た目と検索の規則をそろえる）。
**正本のコードは `lib/utils/spotListSearch.ts`**（先頭のコメントに同じ規則がある）。iOS はこの規則に合わせる。

## 検索の対象

- 画面: Web は `/spots`（`app/components/SpotListSearch.tsx`）。iOS は撮影スポットを探す一覧の最上部
- データ: 公開しているスポットの名前だけの索引。Web は `/app/data/spot-search.json`（`lib/data/spotSearchFeed.ts`・
  アプリの `/app/data/spots.json` と同じ母集合 `visibleSpots`）。1行 = スポット名 `n`・英語名 `e`・読み `r`・別名 `a`・地域 `g`（「山形県 尾花沢市」・海外は「フランス パリ」）・綴り `s`
- 新しい API・費用は足さない。静的に配っている既存の索引を、語が入ったときに1回だけ取る

## 規則

1. **正規化**（比べる前に、入力と各欄の両方へ同じ変換）
   1. NFKC（全角英数・全角記号 → 半角、半角カナ → 全角カナ）
   2. 小文字化
   3. カタカナ → ひらがな（U+30A1〜U+30F6 と ヽヾ を 0x60 引く。長音「ー」は残す）
   4. 空白（全角含む）・中黒（・）・読点（、，,）・括弧（()（）「」『』）・ピリオド（. 。）を落とす
   - 濁点・長音・「ヶ／ケ／が」の揺れは寄せない（別の場所が混ざるため）
2. **語に分ける**: 入力を空白（全角含む）・読点（、，,）で分け、各語を正規化する。空の語は捨てる。最大 6 語。**全部の語が当たる行だけ**が結果（AND）。
   **先に、語を空白なしでつなげた1語として名前の欄に当てる**（当たればその順位で確定。「嵐山 渡月橋」は名前の連続一致を優先）。外れたときだけ語ごとに当てる。
   折りたたみは行ごとに最初に1回だけ
3. **1語が当たる条件**（部分一致）
   - 名前の欄（スポット名・英語名・読み・別名のどれか）に語が含まれる: 完全一致 = 順位 0、前方一致 = 順位 1、部分一致 = 順位 2
   - 地域の欄に語が含まれる: 順位 3
   - 語（2文字以上）が県の読み・英語名の前方なら、その県の名前が地域の欄に含まれていても当たり（順位 3）。
     「やまがた」「yamagata」で山形県のスポットが出る。県の読みの表は `lib/utils/spotListSearch.ts` の `PREFECTURE_READING`
4. **並び**: 行の順位 = 語ごとに当てたときは各語の順位のうち**最も弱い（大きい）もの**（iOS と同じ）。語が無いときは並べ替えない。順位の小さい順、同じ順位は索引の順（台帳の順）。
   つまり **スポット名の前方一致が先**、名前の部分一致、地域だけで当たったものが最後。件数・人気では並べない
5. **県の一覧への近道**: 県（と「海外」）の名前・英語名・読み・綴りに全部の語が含まれるものを、県の一覧への
   チップ（名前＋件数）で出す。名前の前方一致が先・最大 8

## 入力・表示

- 打つたびに絞る（Enter で確定しない）。**変換中（IME の確定前）は絞らず、確定したら絞る**。Enter はキーボードを閉じるだけ
- 空・空白だけは「検索なし」（ふだんの一覧に戻る）
- 結果: 「公開中の撮影スポットのうち N件が当たりました。」を先頭に、既存の一覧の行（`SpotRows`＝丸い印・名前・地域・›）で並べる。
  最初は 30 件、「さらに表示（残りN件）」で 30 件ずつ足す
- 0件: 「「…」の撮影スポットは見つかりません。」と、県名・市区町村名・ひらがなでの検索のヒント。県の一覧（地方ごとのチップ）は残す
- 検索窓: 高さ 44・クリアボタン 44・読み上げの名前「撮影スポットを検索」・プレースホルダー「スポット名・県・エリア」
- Web の URL は `?q=` に残す（履歴は積まない。戻ると復元・共有可）

## 計測（Web・GA4）

`spots_search`（`search_term_length`・`result_count`）。打ち終えて約1.5秒・2文字以上・同じ語は続けて数えない。
**検索語は送らない**（`docs/signup-funnel.md`）。iOS の計測は別（この文書は決めない）。
