# 写真とカメラの教科書 — 執筆の決まり（2026-11-04）

目標: **有料の教材より、わかりやすく・見やすく・内容が濃い**。読んだ人が、次の撮影で写真が変わること。

## 構造

- 1章 = 1ファイル `lib/data/learn/chapters/<slug>.ts`（型は `lib/data/learn/chapterTypes.ts` の `Chapter`）。
  見本は `chapters/focus-and-blur.ts`（**必ず先に読む**。この深さ・この文体・この密度に合わせる）
- 書き終えたら、そのファイルの `export const X: Chapter | null = null;` を `Chapter` に置き換える（登録は済み）
- 節（`sections`）は 6〜9 本。各節は「要点1行 → 短い段落 → 図・表・手順 → 実例 → よくある失敗」
- 章の終わり: `summary`（3〜6点）・`drills`（外で撮る練習 3〜4）・`quiz`（4〜6問・4択・理由つき）・`faq`（2〜4）
- `next` は slug か href（`camera-basics`・`camera-brands`・`composition`・他の章の slug）
- 長さの目安: 1章 約 9,000〜14,000 字（日本語）。水増しはしない。**具体的な手順・数値の目安・失敗例・直し方**で濃くする

## 文章の決まり

- 読者は写真の初心者〜中級者。**専門語は初出で言い換える**（「被写界深度（ピントが合って見える奥行き）」）
- 1段落は 2〜4文。長い段落は表・手順・箇条書きに割る。「〜です／〜ます」で統一
- **推測で書かない。** 数値は「目安」と明記（光・レンズ・機種で変わる）。断定できない一般論は「〜ことがある」
- 値段・発売日・特定の機種や商品の優劣・型番ごとの性能は書かない（すぐ古くなる・誤りやすい）
- メーカーごとに呼び名が違う設定は「呼び名はメーカーで違う」と書く（例: AF-S／ONE SHOT）
- 画面の文字に「撮りどき」「捨てる」「注目スポット」「撮影地ガイド」を使わない
- 写真の他人の権利・安全に関わる話（私有地・人の撮影・ドローン・登山の安全）は、法律の細部に踏み込まず
  「各地の決まりを確かめる」「無理をしない」と書く
- 実測できないこと（画質の優劣の断定・「必ず」「絶対」）は書かない

## 使える部品（`Block`）

`p`・`list`・`table`・`callout`（tip／warn／memo）・`steps`・`diagram`・`example`

- **図**（`diagram`）は `lib/data/learn/diagramIds.ts` の id から選ぶ:
  aperture-sizes・depth-of-field・shutter-motion・exposure-ladder・histogram-shapes・color-temperature・
  focal-angles・light-direction・time-of-day・handheld-rule。**新しい図が要る節は、図の id と内容を報告に書く**
  （図は別に作る。勝手に id を増やさない）
- **実例**（`example`）は `lib/data/learn/cameraBasics.ts` の `EXAMPLE_RULES` の id:
  wide-aperture・narrow-aperture・fast-shutter・slow-shutter・high-iso・wide-angle・telephoto・smartphone。
  合う写真が無ければ画面に出ない（空の枠は作らない）。条件を足したいときは報告に書く

## 確かめ（執筆者は自分でやる）

1. `npx tsc --noEmit -p .` で型が通る
2. 事実を1つずつ確かめる（数値の目安・用語・一般則が一般に言われている通りか）。不確かな箇所は削るか「目安」「ことがある」に
3. 同じ内容が他の章と重なっていないか（`camera-basics.ts` の LESSONS と `focus-and-blur.ts` を読んで、重複は参照に: 「第N章で詳しく」）
4. **報告**: 書いた節の一覧・字数・使った図と実例の id・欲しい新しい図（id と内容）・自信が持てない事実のリスト
