# 作例の写真を目で確かめる担当への指示

journey.photo の撮影スポットのページには、Wikimedia Commons の自由なライセンスの写真を「作例」として最大6枚載せる。
機械が名前と距離で選んだ作例を、**1枚ずつ目で見て**、その撮影スポットの景色として載せてよいかを決める。
あわせて、ページの頭に出す**代表写真を1枚**選ぶ。返答・報告はすべて日本語。ネットには出ない。

## 材料
- 渡された組のファイル（`{{DIR}}/visual/group<N>.json`） … spotId → `{slug, name, files:[{i, path, file, w, h}]}`。`path` は横 1280px の縮小版（Read で見る）
- スポットの中身（名前・分類・説明）: `{{DIR}}/out/<組>.json` の rows（slug で引く）
- 渡された spotId の一覧だけを見る

## 1枚ずつ決めること
**外す**（`exclude` に理由つき）。第2束で外した種類:
- 看板・標識・案内板・石碑だけが主役の写真
- 売店・土産物・料理・商品
- 駐車場・車道・車・バスが主役
- 展示品・室内の展示（そのスポットが博物館で、展示そのものが撮影対象でない限り）
- 手・人物が主役（人が小さく写るのはよい）。祭りの人混みも、スポットが祭りでなければ外す
- 墓所・墓石（そのスポットが墓所でない限り）
- 空からの写真（地上から撮れる景色でない）
- 別の場所が写っている（名前の似た別の寺・別の山など。説明と食い違う景色）
- 暗すぎる・ひどくぼけている・ほとんど何も写っていない・地図や図面・古い絵はがき

**残す**: そのスポットの景色・建物・自然として分かるもの。

**代表写真**（`cover`）: 残した中から1枚。
- そのスポットだと一目で分かる景色・外観
- 横長を優先（縦長しか良いものが無ければ縦長でよい）
- 人が主役でないもの
- 良い1枚が無ければ `null` にして理由を書く

## 出すもの
`{{DIR}}/visual/<担当名>.json` に:
```json
{"<spotId>": {"slug": "…", "exclude": [{"i": 2, "reason": "看板が主役"}], "cover": 0, "note": "（任意）"}}
```
- `i` は index.json の `i`
- 全部の写真を実際に Read で見てから決める（見ずに決めない）
報告: 見たスポット数・見た枚数・外した枚数（理由の内訳）・代表写真を付けたスポット数・付けなかったスポットと理由。

## 第4束で分かったこと（必ず守る）
- **開いて見た写真だけ決める。** 画像が返らない（request limit・`[media removed]`）ときは、ファイル名や説明から推して決めない。
  少し間を置いて開き直し、それでも見られなければ `pending`（2枚目以降）か `"unviewed": true`（1枚目）にする。81 枚を渡した担当が
  途中から見ずに決め、全部やり直しになった
- 外す型（多かった順）: 空からの写真（ドローン・飛行機の窓・宇宙ステーション）、建物・看板・料金表・石碑・案内板が主役、
  古い絵・浮世絵・奉納額、別の山・別の場所（ファイル名が別の山の名前）、展示物・商品、人物が主役、ほとんど何も写っていない、工事中
- そのスポットで撮った写真か確かめられない（ファイル名に地名が無く景色から決められない）ものは外す方に倒す
- 代表写真は「そのスポットだと一目で分かる」もの。山の名前の山頂の祠・標柱だけ、城跡の草の斜面だけは代表にしない
