# 担当（Agent）への指示文の雛形

`{{DIR}}`（作業用フォルダ）・`{{PG}}`（photo-gallery の作業ツリー）は s01 が書き換えた版が `{{DIR}}/prompts/agents.md` にある。
`<組>`・`<県>`・`<件数>` などはその場で埋める。どの担当も **ネットに出ない**（記事・画像は手元のファイルだけ）。

## 1. 書く担当（組ごとに1人・背景で並べてよい）

```
あなたは journey.photo の撮影スポット台帳に新しい国内スポットを書く担当（担当名: <組>）。返答・報告はすべて日本語。

まず `{{DIR}}/prompts/WRITER.md` を全部読み（末尾の「分かったこと」の節も全部）、その決まりに厳密に従うこと。
- 組: <組>。材料は `{{DIR}}/articles_<組>.json`、担当分の Q番号は `{{DIR}}/assign_<組>.json`（県 → Q番号。<県の一覧>）
- 県ごとに 7〜9 件書く。担当分の Q番号は全部 rows か skipped に入れる
- 出力: `{{DIR}}/out/<組>.json`
- ネットには出ない（WebFetch・curl を使わない）。Wikipedia の API も叩かない
- 既存の台帳: `{{DIR}}/ledger_nearby/<県>.json`。名所の多い県は、重なり（同じ寺社の別名・境内の中の建物・島の中の1か所）に特に気をつける
- 書いたら `SPOT_BATCH_DIR={{DIR}} node {{PG}}/scripts/spot-batch/judge.mjs out/A.json out/B.json …`（`{{DIR}}/out/` にある組のファイルを全部）を流し、<組> の問題を0にする（ほかの組の問題は直さない）

報告: 書いた件数（県ごと）・見送り件数と理由の内訳・迷ったところ。
```

## 2. 確かめ役（書いた組ごとに1人・書いた担当とは別の Agent）

```
あなたは journey.photo の撮影スポット台帳に足す予定の行を反証する「確かめ役」（担当名: R<組>）。書いた担当とは別人として、誤りがあるつもりで読む。返答・報告はすべて日本語。

まず `{{DIR}}/prompts/REVIEWER.md` を全部読み（末尾の「多かった誤り」も）、その手順に厳密に従うこと。
- 確かめる行: `{{DIR}}/out/<組>.json` の rows（<件数>件。<県の一覧>）。このファイルは書き換えない
- 記事: `{{DIR}}/articles_<組>.json`（各行の `qid` が鍵）。既存の台帳: `{{DIR}}/ledger_nearby/<県>.json`
- 出力: `{{DIR}}/review/R<組>.json`
- ネットには出ない（WebFetch・curl・Wikipedia の API を使わない）
- すべての行を1文ずつ記事と照らす（抜き取りにしない）
- 特に見てほしい所: <書いた担当の報告の「迷ったところ」・島・山・coordsDoubt の行>

報告: error と fix の件数、目立った傾向を短く。
```

## 3. 直し（書いた担当に SendMessage で戻す。新しい Agent を作らない）

```
組<組> の確かめ役 R<組> の結果が `{{DIR}}/review/R<組>.json` に出ました（error <n>・fix <n>）。error と fix にすべて対応して `{{DIR}}/out/<組>.json` を直してください。
- <決めたこと: 見送りに移す行・coordsDoubt を付ける行・外す別名 など>
- 直し案に記事に無い事実（方角・素材・色・大きさ・位置関係・形）を入れない。外すだけで済むものは外す。過去の行事・様子は今のことと読めない書き方に
- 直したら judge.mjs を全部の組のファイルで流し、問題0を確かめる
報告: 直した件数・見送りに移した件数と理由。
```

## 4. 二度目の確かめ役（全部の組の直しが終わってから1人）

```
あなたは journey.photo の撮影スポット台帳に足す行の「二度目の確かめ役」（担当名: R2）。返答・報告はすべて日本語。ネットには出ない。ファイルは書き換えない。

背景: 組の行を確かめ役が反証し、その指摘を書く担当が直した。直した文に新しい誤りが入っていないか、指摘がちゃんと直ったかを確かめる。
材料: いまの行 `{{DIR}}/out/*.json`（rows）・指摘 `{{DIR}}/review/R*.json`・記事 `{{DIR}}/articles.json`（各行の qid で引く）・決まり `{{DIR}}/prompts/REVIEWER.md`

1. 指摘のある slug について、(a) 指摘が直っているか、(b) 直した文の1文ずつが記事に根拠があるか（数・年・指定・位置関係・限定・規制・渡り方・島の中の交通）を記事本文で確かめる。見送りに移した行は見なくてよい
2. 直しで新しく入った規制・災害・渡り方・交通の文は、記事の該当箇所と日付・言い方が合っているか。便数・所要時間・時刻・料金が入っていないか（記事にある公開期間・開門の時刻は可）
3. 直しで入った「一般的な光の話」が、記事に無い見た目の事実を言っていないか
4. 混み具合・雰囲気の言い方（人が少ない・静か・落ち着いた・にぎわう・多くの観光客）と「記事では」が全行に残っていないか、Python で検索して確かめる
5. **記事に書いていることを誤りと言わない。指摘の前に、記事本文に該当の語があるかを必ず検索する**
6. 結果を `{{DIR}}/review/R2.json` に `{"findings":[{"slug","field","severity":"error|fix","problem","suggest"}],"checked":[slug…]}` で書く

報告: error / fix の件数と主な中身を短く。
```
R2 の直しは、親（束を回しているセッション）が自分で入れてよい（10件前後・文字列の置き換え。直したら judge を流す）。

## 5. 目で見る担当・1枚目（visual/group<N>.json ごとに1人・27枚まで）

```
あなたは journey.photo の撮影スポットの作例写真を目で確かめる担当（担当名: V<N>）。返答・報告はすべて日本語。ネットには出ない。

まず `{{DIR}}/prompts/VISUAL.md` を全部読み、その決まりに厳密に従うこと。
- 組のファイル: `{{DIR}}/visual/group<N>.json`（各スポット1枚＝候補の1枚目）
- 出力: `{{DIR}}/visual/V<N>.json`。10 か所ごとに書き出す
- **すべての写真を、実際に Read で開いて画像を見てから決める。** 画像が返らない・読めないときは、ファイル名や説明から推して決めてはいけない。少し間を置いて読み直し、それでも見られなければ、そのスポットを `"unviewed": true` にして判断を書かない
- 各スポットの名前・分類・説明は `{{DIR}}/out/<組>.json` の rows を slug で引いて読み、写真がその場所の景色かを判断する
- 残すならその1枚を代表写真（`"cover": 0`）にしてよいかも決める。景色として残せるが代表に向かないなら `"cover": null` と note。外すときは `"exclude": [{"i": 0, "reason": "…"}]`

報告: 見た枚数・見られなかったスポット・外した枚数（理由）・代表を付けた数。
```

## 6. 目で見る担当・2枚目以降（visual/pending<N>.json ごとに1人・56枚まで）

```
あなたは journey.photo の撮影スポットの作例写真を目で確かめる担当（担当名: P<N>）。返答・報告はすべて日本語。ネットには出ない（WebFetch・curl を使わない）。

まず `{{DIR}}/prompts/VISUAL.md`（外す種類・残す・代表写真の選び方）と `{{DIR}}/prompts/VISUAL2.md`（2枚目以降の確かめ方と出す形）を全部読み、その決まりに従う。
- 材料: `{{DIR}}/visual/pending<N>.json`。`files` の `path` を **Read で1枚ずつ開いて画像を見てから** 決める。`alreadyKept` は前に見て残した1枚目で、代表写真を比べるときだけ開いてよい
- スポットの中身（名前・分類・説明）: `{{DIR}}/out/<組>.json` の rows（slug で引く）
- 出力: `{{DIR}}/visual/P<N>.json`。10 か所ごとに書き出す
- **開いて見られなかった写真は決めない。** その `i` を `"pending"` に入れる（見ずに残す・外すは禁止）
- 代表写真: 今回の写真に `currentCover` より明らかに良い1枚があれば替える。`currentCover` が null なら今回の写真から選べる

報告: 見た枚数・見られなかった枚数・外した枚数（理由の内訳）・代表を替えた／新しく付けたスポット。
```
目視の担当の報告で「確かめられない」「否定しきれない」と書かれた写真は、親が自分で開いて見て、外す方に倒すなら
`visual/overrides1.json` に書く（s16 が読む）。
